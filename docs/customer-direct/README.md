## Scope and precedence

This is the executable backlog for CUSTOMER_DIRECT_IMPLEMENTATION_PLAN.md. All UI/UX/frontend work exclusively uses GDS, including basic branding and advanced customization. Unrestricted custom CSS is superseded by approved GDS token/extension contracts. Accessibility, internationalization and explicit currency accounting start in the foundation.

The repository stays moldovancsaba/deliafrica; customer.direct is the platform/product name. No repository rename or application rollout was performed by this planning change.

## Board operation

- Delivery board: status columns Todo, In Progress, Done.
- Execution sequence: items inserted in topological order, with an explicit numeric Execution order field.
- Ready to start: Readiness:Ready.
- Later benefits: Readiness:Later; M6 is not part of initial launch.
- Labels identify area, priority, GDS, a11y and tenant-isolation requirements.
- Native blocked-by relationships are authoritative; issue bodies repeat links for handover context.
- On predecessor completion, check its handover before updating dependent Readiness and execution label. No automatic readiness synchronization is claimed.
- Assignees and due dates are intentionally unset until someone takes ownership and establishes a schedule.
- Keep work Todo while blocked; move to In Progress when execution starts. Done requires evidence, not a merged PR alone.

## Delivery gates

Each runtime slice requires tests, documentation, release notes, commit/push, Vercel Production READY for the intended commit and relevant safe runtime verification. Keep incomplete new platform capabilities feature-gated. No production data seeding, test payments or messaging without the appropriate operational authorization. Documentation-only slices do not require an artificial runtime deployment.

## Milestones

- **M1 — Verified platform foundations:** Baseline, GDS, localized messages, isolated registry, secrets and access contracts.
- **M2 — Shop isolation and administration:** Per-shop access, configuration, catalogue, customer boundaries and secure central dashboard.
- **M3 — Localized commerce and integrations:** Exact multicurrency orders, inventory, delivery, payment, invoicing and consent-aware analytics.
- **M4 — GDS storefront and self-service launch:** Localized content, assets, governed branding, domains, lifecycle and health.
- **M5 — Migration and production pilot:** Shared identity, discount.direct preparation, exports, isolation/a11y evidence and controlled deli migration.
- **M6 — Participating-shop benefits (later):** Campaign-specific benefits after discount.direct redemption readiness; no universal balance.
